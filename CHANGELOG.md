# Changelog

All notable changes are recorded here. This project follows semantic versioning.

## Unreleased

- Fix README version badge to match current runner version (1.11.0).
- Regenerate dashboard backend lockfile against public package indexes.
- Reinstall dashboard frontend dependencies to restore executable permissions.
- Wire up dashboard run exclusions: local-storage persistence, API filters, and UI actions.
- Rename legacy base-path configuration key and CLI flag to `path_base` / `--path-base`; remove all company-specific examples and URLs from documentation.
- Remove private company package-index references from the dashboard backend lockfile.

## 1.11.0 - 2026-10-16

- Add native Strix session resumption by history ID, run ID, or run directory.
- Add `resume list` to show only runs with restorable agent state.
- Validate the persisted agent topology and SDK session database before resuming.

## 1.10.0 - 2026-10-08

- Add a separate read-only Python and React dashboard for the complete Strix history.
- Add cached filtering, pagination, stable run IDs, aggregate metrics, trends, and run comparison.
- Serve penetration reports through a path-contained, size-bounded read-only API.
- Keep dashboard dependencies isolated from the standard-library runner.

## 1.9.2 - 2026-10-08

- Accept history IDs as a positional value, through `--run`, or through `--id` without requiring `--all`.

## 1.9.1 - 2026-10-08

- Display chronological selection IDs in `history` and accept them through `--run`.

## 1.9.0 - 2026-10-08

- Add `history` to inspect Strix executions by application and date.
- Export the normalized history model as JSON or a dependency-free standalone HTML report.
- Read persisted agents and their loaded skills without opening message transcripts.
- Report skill utility only when an explicit structured audit provides evidence.
- Persist private `strix-runner.json` provenance records for newly correlated runs.

## 1.8.0 - 2026-10-05

- Supervise local applications through explicit POSIX process-group identities.
- Terminate remaining children even when the original parent has already exited.
- Escalate from `SIGTERM` to `SIGKILL` after configurable `stop_grace_seconds`.
- Disconnect application and stop-command stdin from the Strix terminal.
- Record application PID, PGID, and lifecycle signals in the protected log.

## 1.7.0 - 2026-10-05

- Correlate every profile with the structured artifacts generated by Strix.
- Print per-profile executive summaries and an aggregate final result table.
- Persist private `summary.json` and `summary.md` files for each runner batch.
- Distinguish completed findings, incomplete scans, missing reports, and errors.
- Continue batch execution after Strix exit code 2 when artifacts prove completion.
- Add numeric selection IDs to `list` and accept IDs in `run`.
- Add complete configuration examples to `save --help` and `list`.

## 1.6.0 - 2026-10-02

- Add `--only-code` to scan configured repositories without local app lifecycle.
- Add `--only-pentesting` to scan configured URLs without code targets.
- Keep the default behavior as all targets and retain legacy `--code-mode`.

## 1.5.0 - 2026-10-01

- Capture application start/stop output in protected per-run log files.
- Add global `log_dir` configuration and per-run `--app-log-dir` overrides.
- Keep Strix attached to the terminal and avoid log creation during `--dry-run`.

## 1.4.0 - 2026-10-01

- Persist optional `additional_instruction_file` values per profile.
- Allow per-run instruction-file overrides.

## 1.3.0 - 2026-10-01

- Support multiple `urls` and `code_paths` per profile.
- Add `command_cwd` for local lifecycle commands with multiple repositories.

## 1.2.0 - 2026-10-01

- Add `verify` and `verify --json-only`.

## 1.1.0 - 2026-10-01

- Improve configuration validation, cleanup, portability, and `--keep-going`.
- Add per-run additional instruction files.
